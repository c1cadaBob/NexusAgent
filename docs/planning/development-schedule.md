# NexusAgent 开发排期基线

> 文档状态：P0-08 排期基线。本文把现有 P0-P8 人天估算转换为可执行日历排期，用于后续迭代计划、阶段门禁和资源协调。
>
> 工时说明：人天仅为工程估算，会受上游开源版本变更影响。
>
> 基线口径：截至 `2026-08-23` UTC，本排期仅锁定阶段顺序、关键路径和重排规则；团队容量、地区节假日、公司发布冻结窗口和生产基础设施标准仍是【待确认问题】。

## 1. 排期假设

| 项目 | 基线假设 |
|---|---|
| 排期起点 | `2026-08-24`，即当前日期 `2026-08-23` 后的第一个工作日 |
| 工作周 | 周一至周五，暂不扣除地区节假日；如需扣除节假日，P0 结束前更新本文件 |
| 估算口径 | 完整规划基线为 `201` 人天，其中功能开发本体为 `198` 人天，P0-08 排期治理为 `1` 人天，P0-09 AI 排期提示词治理为 `1` 人天，P0-10 任务提示词文档生成为 `1` 人天 |
| MVP 范围 | P0-P6 必选，交付统一 API、平台内核、三个内部 adapter、基础控制台、E2E、安全和降级验证 |
| 可裁剪范围 | P7 高级特性可延后；P8 Kubernetes 高级交付可分批，但生产编排、安全和运维文档不能省略 |
| 资源假设 | 核心 8 个职能角色并行：架构/产品、平台内核、上游改造、API、前端、测试、SRE、安全/合规；每阶段按主责团队投入，不要求所有角色全时 |
| 阶段推进 | 阶段门禁未通过不得进入依赖阶段；P2/P3/P4 可在 P1 完成后并行推进 |

### 1.1 基线边界

| 边界 | 排期处理方式 |
|---|---|
| P0-P6 MVP 主线 | 不裁剪；任一门禁失败必须先完成回退或重排评审，再进入后续依赖阶段 |
| P7 高级能力 | 默认不阻塞 MVP；只有产品负责人明确列为首版必选时才进入关键路径 |
| P8 生产交付 | 不等同于 MVP 冻结，但生产编排、安全、监控、备份恢复和交付手册必须完成后才能生产发布 |
| 团队容量 | 8 个职能角色只是并行能力模型，不代表已确认编制；实际人数低于基线时按第 7 节重排 |
| 日历约束 | 暂不扣除地区节假日和发布冻结窗口；确认后按第 10 节触发重算 |
| 上游版本 | 三大上游只作为 vendor/provider 输入；版本漂移触发阶段风险评审，不直接改公共契约 |

## 6. 关键路径

```text
P0 可行性门禁
  -> P1 平台内核与公共契约
  -> P2/P3/P4 三个 adapter 并行接入
  -> P5 对外 API、控制台、SDK
  -> P6 E2E、安全、故障和降级验收
  -> MVP 冻结
  -> P8 生产交付
```

关键路径上最大的不可压缩点是 P0 剥离实验、P1 公共契约、P2-P4 adapter 防绕过验证和 P6 安全闭环。P7 不进入 MVP 关键路径，除非产品负责人明确把某项高级能力列为首版必选。

## 7. 资源容量与压缩/延后规则

| 场景 | 日历影响 | 调整方式 |
|---|---|---|
| 资源低于基线，只有 4-5 名核心开发 | MVP 预计延后 4-6 周 | P2/P3/P4 改为两批执行；P5 控制台高级页延后；P7 全部移出首版 |
| 资源达到 8-10 名核心开发且上游实验顺利 | MVP 可维持 2026-11-27 冻结 | P2/P3/P4 并行；P5 API/前端/SDK 并行；P8 提前准备 CI 和运维文档 |
| Hermes planner-only 失败 | MVP 不延后超过 1 周 | 启动轻量化路线：保留 OpenClaw + DSH，关闭 Hermes 和高级记忆 |
| DSH executor-only 失败 | P2 阻塞，MVP 日期必须重估 | 暂停 P5 完整开发，只保留平台外壳和 API 契约；评估替代执行后端 |
| OpenClaw gateway-only 失败 | MVP 渠道能力降级 | 首版只保留平台 API 入口，渠道管理延后或只保留一个已验证渠道 |
| 生产基础设施选型迟迟未定 | P8 可能延后，但不阻塞 MVP | P1/P5 使用抽象接口和开发默认实现；P8 前再绑定企业标准实现 |

### 7.1 角色容量模型

| 职能角色 | 基线职责 | P0-P6 MVP 最小投入 | 容量不足时的降级处理 |
|---|---|---|---|
| 架构/产品 | 范围裁决、阶段门禁、降级路线、待确认问题闭环 | 每周参与门禁和风险复盘 | 未裁决项保留为【待确认问题】，不得写成事实 |
| 平台内核 | contracts、Coordinator、Policy-Gate、状态机、事件、凭据、memory/artifact 接口 | P1-P6 持续投入 | P2-P4 不并行，先保 P1/P5 主链路 |
| 上游改造 | OpenClaw/Hermes/DSH provider、剥离、防绕过和补丁登记 | P0、P2-P4、P6 高投入 | 优先 DSH + OpenClaw，Hermes 高级记忆可降级 |
| API/SDK | REST/gRPC、OpenAPI、SDK、契约测试 | P5 高投入，P0/P1 参与契约 | gRPC 延后为 P5/P8 待确认，不阻塞 REST MVP |
| 前端 | Web 控制台、渠道/插件治理视图、审计和监控页面 | P5 高投入 | 高级页面延后，保留任务、审批、健康和审计核心页 |
| 测试/安全 | 单元、契约、E2E、防绕过、恶意插件和凭据泄漏测试 | P0-P6 持续投入 | 不压缩防绕过、安全和 smoke；只能压缩非关键 UI 验收 |
