# P0 Hermes planner-only 剥离实验记录

> 文档状态：P0-03 实验记录。本文记录 Hermes 作为 NexusAgent 内部 planner provider 的最小剥离证据，不代表 P3 生产 provider 已完成。

## 1. 实验结论

- P0-03 在 NexusAgent 内部 Hermes vendor 快照中加入 opt-in 实验开关 `NEXUS_HERMES_PLANNER_ONLY=1`。
- 开启实验开关后，`run_conversation` 不进入 Hermes 原生 LLM/tool/final-response 大循环，而是直接返回平台 `ExecutionPlan` handoff，`final_response` 固定为空字符串。
- 开启实验开关后，并发和串行 tool executor 只追加结构化 blocked tool result，不调用 `agent._invoke_tool(...)`、context tool 或 memory provider tool。
- 开启实验开关后，内置文件记忆不读取、不创建、不写入 `MEMORY.md` / `USER.md`；写入必须迁移到平台 Memory Gateway。
- 开启实验开关后，原生 `/loop` 不能创建或恢复 recurring agent turn，已存在 tick 会被暂停，不再注入新的用户 turn。
- 本实验不修改 `/opt/project/hermes-agent-main` 原始目录；所有补丁只落在 `/opt/project/NexusAgent/vendor/hermes-agent-main`。

## 2. 调用图

```text
platform task request
  -> platform/adapters/hermes/  [P3 production boundary, P0 not implemented]
  -> vendor/hermes-agent-main/agent/conversation_loop.py
  -> [P0-03 guard] build ExecutionPlan when NEXUS_HERMES_PLANNER_ONLY=1
  -> return { final_response: "", execution_plan, nexus_planner_only: true }

native tool request generated by Hermes model output
  -> agent/tool_executor.py
  -> execute_tool_calls_concurrent / execute_tool_calls_sequential
  -> [P0-03 guard] append blocked tool result
  -> native _invoke_tool / context tool / memory provider tool is not called

native file memory
  -> tools/memory_tool.py
  -> MemoryStore.load_from_disk / add / replace / remove / apply_batch / _write_file
  -> [P0-03 guard] no MEMORY.md or USER.md read/write; return Memory Gateway required

native recurring loop
  -> hermes_cli/loops.py
  -> dispatch_loop_command / LoopManager.fire_tick
  -> [P0-03 guard] block create/resume and pause existing tick
```

## 5. 保留、隔离和禁止入口

| 入口类型 | P0-03 决策 | 说明 |
|---|---|---|
| Planning reasoning | 保留候选 | P0-03 仅证明输出边界和阻断点；P3 再把真实 planning inference 接入标准 `ExecutionPlan`。 |
| Skills / MCP / planning plugins | 保留候选 | 可作为 P3 planner provider 的能力来源，但不能直接执行工具或直读记忆。 |
| Native final natural-language answer | 禁止 | planner-only 模式只输出结构化计划，产品层最终回复由平台链路决定。 |
| Native tool runtime | 禁止 | 工具执行必须经过 Coordinator、Policy-Gate、Credential Center、Artifact Store 和 DSH executor。 |
| Native file memory | 禁止 | `MEMORY.md` / `USER.md` 不作为平台公共存储；生产隔离由 Memory Gateway 和 sidecar 文件权限完成。 |
| Native recurring loop | 禁止 | 长任务、调度和继续语义后续由平台 Coordinator/clock 管理。 |

## 6. 回归测试清单

- `vendor/hermes-agent-main/tests/agent/test_nexus_planner_only_experiment.py`：验证 `ExecutionPlan` shape、空 `final_response`、tool executor 阻断、memory provider 阻断和文件记忆拒绝。
- `vendor/hermes-agent-main/tests/hermes_cli/test_nexus_planner_only_loop.py`：验证 `/loop` 创建/恢复/tick 注入阻断。
- `tests/smoke/P0.sh`：验证 P0-03 决策文档存在、P0-03 审计记录不保留占位、`ExecutionPlan` schema 存在、vendor 未引入依赖缓存。
- 当前环境未安装 pytest 且系统 Python 为 3.14.4，不满足 Hermes `>=3.11,<3.14`；本轮以 `py_compile`、轻量导入脚本和 P0 smoke 作为替代验证，完整 pytest 需在 P3/P6 使用 Python 3.13 或项目 `.venv` 重跑。

## 7. 回滚方式

1. 删除或关闭运行环境中的 `NEXUS_HERMES_PLANNER_ONLY`，默认 Hermes 行为保持不变。
2. 若需回退补丁，撤销以下文件变更：`agent/nexus_planner_only_experiment.py`、`agent/conversation_loop.py`、`agent/tool_executor.py`、`agent/memory_manager.py`、`tools/memory_tool.py`、`hermes_cli/loops.py` 及对应测试。
3. P3 正式改造前不得把本实验开关视为生产安全边界；生产边界必须迁移到 `platform/adapters/hermes/`、Memory Gateway、Policy-Gate 和 sidecar 文件权限。

## 8. 待确认问题

- Hermes upstream remote、release commit 和 fork 分支仍无法从本地快照确认。
- Hermes 五层记忆的正式层级、保留期、冲突策略和平台 Memory Gateway 存储选型仍需确认。
- P3 生产 planner provider 是使用 HTTP/gRPC sidecar、stdin/stdout RPC，还是直接 Python package embedding，仍需架构评审。
- P0-03 仅能证明 Hermes 进程内拒绝文件记忆；外部进程无法直接读写 `MEMORY.md`/`USER.md` 需要 P3/P6 通过容器挂载、文件权限和安全测试完成。
